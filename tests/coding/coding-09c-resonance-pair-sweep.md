## Task

A geophone array records a stream of integer ground-motion readings.
Implement `resonantPairs(readings, target)`: it returns the number of
index pairs `i < j` such that `readings[i] + readings[j] === target`
(a "resonant pair" is two samples whose amplitudes sum to the target).

The catch: you must NOT use a naive nested double-loop over the full
stream to count pairs. To make this mechanically checkable without any
timing flakiness, your file must maintain a global integer variable
`SAMPLE_READS` (start it at 0) and increment it by exactly 1 for every
single element your OWN explicit loop code reads from `readings` (or
from any array you derive from `readings`, such as a sorted copy) while
counting pairs. Concretely: every time a `for`/`while` loop you wrote
indexes into `readings` or a same-length derived array to read a value,
that is one increment. You do NOT need to (and should not) count
comparisons that happen inside a built-in sort's comparator function —
sorting the readings is allowed, and the internal comparisons
`Array.prototype.sort` performs are exempt from `SAMPLE_READS` (only the
reads in loops you write yourself count).

Two acceptable strategies: a single hash-map pass (look up
`target - v` as you go), or a sort-then-two-pointer scan. Both satisfy
the budget below; a nested double loop over the full stream does not.

## Deliverables

- `resonance.js` — exports `resonantPairs(readings, target)` via
  `module.exports`. When run with `node resonance.js`, it must:
  - Print the count for each of the two small vectors below.
  - Generate the 18000-element stream described below, print the count
    for it (using a target of your choice is fine for your own printed
    demonstration, but see the pinned target used for grading below),
    and print the final `SAMPLE_READS` on its own line in the exact
    format `SAMPLE_READS=<n>` after processing the 18000-element stream
    with target `179096`.

Small correctness vectors:

```js
resonantPairs([5,4,-1,4,9,0,5,13,-4,7,4,1,8,2,11,6,3,10,4,5], 9);
resonantPairs([7,7,7,7,7], 14);
```

The 18000-element stream must be generated by this exact linear
congruential recurrence (so the judge can regenerate identical data):
start with `x = 3`, then for each of the 18000 elements, update
`x = (x * 1664525 + 1013904223) % 90000` BEFORE pushing it (so the
first pushed value is the result of the first update, not the seed
itself). In JavaScript:

```js
function genReadings(n) {
  let x = 3;
  const arr = [];
  for (let i = 0; i < n; i++) {
    x = (x * 1664525 + 1013904223) % 90000;
    arr.push(x);
  }
  return arr;
}
```

Run `resonantPairs` on this generated stream with `target = 179096` for
the `SAMPLE_READS` measurement described above.

## Constraints

- Plain JavaScript, no dependencies, single file, at most 90 lines.
- No nested loop over the full input for the counting logic itself
  (a single hash pass, or a sort followed by a single linear scan, are
  both fine).
- `SAMPLE_READS` must stay within budget for the 18000-element run —
  see the objective checks for the exact bound.
