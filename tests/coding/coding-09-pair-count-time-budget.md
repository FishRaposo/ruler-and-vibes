## Task

Implement `countPairs(arr, target)`: it returns the number of index
pairs `i < j` such that `arr[i] + arr[j] === target`.

The catch: you must NOT use a naive nested double-loop over the full
array to count pairs. To make this mechanically checkable without any
timing flakiness, your file must maintain a global integer variable
`OP_COUNT` (start it at 0) and increment it by exactly 1 for every
single element your OWN explicit loop code reads from `arr` (or from
any array you derive from `arr`, such as a sorted copy) while counting
pairs. Concretely: every time a `for`/`while` loop you wrote indexes
into `arr` or a same-length derived array to read a value, that is one
increment. You do NOT need to (and should not) count comparisons that
happen inside a built-in sort's comparator function — sorting the
array is allowed, and the internal comparisons `Array.prototype.sort`
performs are exempt from `OP_COUNT` (only the reads in loops you write
yourself count).

Two acceptable strategies: a single hash-map pass (look up
`target - x` as you go), or a sort-then-two-pointer scan. Both satisfy
the budget below; a nested double loop over the full array does not.

## Deliverables

- `pairs.js` — exports `countPairs(arr, target)` via
  `module.exports`. When run with `node pairs.js`, it must:
  - Print the count for each of the two small vectors below.
  - Generate the 20000-element array described below, print the count
    for it (using a target of your choice is fine for your own
    printed demonstration, but see the pinned target used for grading
    below), and print the final `OP_COUNT` on its own line in the
    exact format `OP_COUNT=<n>` after processing the 20000-element
    array with target `198490`.

Small correctness vectors:

```js
countPairs([2,7,11,15,2,7,-4,3,8,0,15,11,4,6,1,9,2,13,5,10], 9);
countPairs([3,3,3,3], 6);
```

The 20000-element array must be generated by this exact linear
congruential recurrence (so the judge can regenerate identical data):
start with `x = 1`, then for each of the 20000 elements, update
`x = (x * 1103515245 + 12345) % 100000` BEFORE pushing it (so the
first pushed value is the result of the first update, not the seed
itself). In JavaScript:

```js
function genArray(n) {
  let x = 1;
  const arr = [];
  for (let i = 0; i < n; i++) {
    x = (x * 1103515245 + 12345) % 100000;
    arr.push(x);
  }
  return arr;
}
```

Run `countPairs` on this generated array with `target = 198490` for
the `OP_COUNT` measurement described above.

## Constraints

- Plain JavaScript, no dependencies, single file, at most 90 lines.
- No nested loop over the full input for the counting logic itself
  (a single hash pass, or a sort followed by a single linear scan, are
  both fine).
- `OP_COUNT` must stay within budget for the 20000-element run — see
  the objective checks for the exact bound.
