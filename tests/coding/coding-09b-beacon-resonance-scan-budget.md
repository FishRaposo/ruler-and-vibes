## Task

A radio survey logs the frequency offsets of navigation beacons. Two
beacons are said to *resonate* at a chosen `resonance` value when the
sum of their offsets equals that value. Implement
`countResonantPairs(offsets, resonance)`: it returns the number of index
pairs `i < j` such that `offsets[i] + offsets[j] === resonance`.

The catch: you must NOT use a naive nested double-loop over the full
array to count the resonant pairs. To make this mechanically checkable
without any timing flakiness, your file must maintain a global integer
variable `SCAN_READS` (start it at 0) and increment it by exactly 1 for
every single element your OWN explicit loop code reads from `offsets`
(or from any array you derive from `offsets`, such as a sorted copy)
while counting pairs. Concretely: every time a `for`/`while` loop you
wrote indexes into `offsets` or a same-length derived array to read a
value, that is one increment. You do NOT need to (and should not) count
comparisons that happen inside a built-in sort's comparator function —
sorting the array is allowed, and the internal comparisons
`Array.prototype.sort` performs are exempt from `SCAN_READS` (only the
reads in loops you write yourself count).

Two acceptable strategies: a single hash-map pass (look up
`resonance - x` as you go), or a sort-then-two-pointer scan. Both
satisfy the budget below; a nested double loop over the full array does
not.

## Deliverables

- `resonance.js` — exports `countResonantPairs(offsets, resonance)` via
  `module.exports`. When run with `node resonance.js`, it must:
  - Print the count for each of the two small vectors below.
  - Generate the 24000-element array described below, print the count
    for it (using a resonance value of your choice is fine for your own
    printed demonstration, but see the pinned resonance used for grading
    below), and print the final `SCAN_READS` on its own line in the
    exact format `SCAN_READS=<n>` after processing the 24000-element
    array with resonance `86672`.

Small correctness vectors:

```js
countResonantPairs([5,3,11,14,5,3,-6,4,7,0,14,11,6,8,1,10,5,12,2,9], 8);
countResonantPairs([5,5,5,5,5], 10);
```

The 24000-element array must be generated by this exact linear
congruential recurrence (so the judge can regenerate identical data):
start with `x = 1`, then for each of the 24000 elements, update
`x = (x * 75893 + 25943) % 45000` BEFORE pushing it (so the first pushed
value is the result of the first update, not the seed itself). In
JavaScript:

```js
function genOffsets(n) {
  let x = 1;
  const arr = [];
  for (let i = 0; i < n; i++) {
    x = (x * 75893 + 25943) % 45000;
    arr.push(x);
  }
  return arr;
}
```

Run `countResonantPairs` on this generated array with `resonance = 86672`
for the `SCAN_READS` measurement described above.

## Constraints

- Plain JavaScript, no dependencies, single file, at most 90 lines.
- No nested loop over the full input for the counting logic itself
  (a single hash pass, or a sort followed by a single linear scan, are
  both fine).
- `SCAN_READS` must stay within budget for the 24000-element run — see
  the objective checks for the exact bound.
